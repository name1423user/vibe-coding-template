# Phase 4 環境を作る

## このフェーズの目的

機能を作り始める前に、「何もしないが起動はする」状態を作る。
先に機能を作り、後から環境を整えようとすると、動く部分と動かない部分が混ざり、どこが原因か切り分けられなくなる。空のアプリが起動することを確認してから、初めて機能を積み上げる。
このフェーズは詰まりやすい。詰まったら付録Dのトラブルシューティングを開く。

## 成果物

- Gitリポジトリと最初のコミット
- 起動するだけの空のアプリ
- `.gitignore`
- `.env.example`

## 手順

1. アプリ用のフォルダを作り、Gitリポジトリを初期化する
2. 必要なライブラリを導入する。ReadLogならExpress、SQLiteを扱うライブラリ、セッション管理用のライブラリ、パスワードのハッシュ化用のライブラリ、EJSを入れる
3. 画面も機能も持たない、起動するだけの最小のコードを書く。ブラウザで開いて何か表示されれば成功だ
4. 秘密情報の置き場所を決める。パスワードやセッションの署名に使う値は、コードに直接書かず環境変数として扱う。環境変数とは、コードの外側に置く設定値のことだ。値を変えるときにコードを書き換えずに済む
5. `.gitignore` と `.env.example` を用意し、ここまでの状態をコミットする

`.gitignore` は、Gitに記録しないファイルを指定する設定ファイルだ。秘密情報を含む実際の設定ファイルをここに書いておけば、誤ってGitに記録することを防げる。
`.env.example` は、環境変数の実際の値を書かず、必要な項目名だけを示す見本ファイルだ。他の人がこのアプリを動かすとき、どの項目を自分で埋めればよいかが分かる。

ReadLogのフォルダ構成は次のとおりにした。

```
readlog/
  package.json
  .gitignore
  .env.example
  src/
    app.js        画面・処理の入口
    routes/       処理（バックエンド）
    views/        画面（フロントエンド）
    db/           保存（データベース）
```

## AIへのプロンプト雛形

> 〇〇（技術スタック）で、画面も機能もまだ持たない、起動するだけの最小構成を作ってください。フォルダ構成は次のとおりにしてください。起動確認の手順も併記してください。
>
> 〇〇

秘密情報の洗い出しには別のプロンプトを使う。

> このアプリで扱う秘密情報を洗い出し、`.env.example` に書くべき項目名と、`.gitignore` に追加すべきファイルを提案してください。値そのものは書かないでください。

## 完了条件

- [ ] Gitリポジトリを作り、最初のコミットをしている
- [ ] 何もしないアプリが起動する
- [ ] `.gitignore` に秘密情報を含むファイルを追加している
- [ ] `.env.example` に必要な項目名を書いている

## よくある失敗と戻り先

**機能を作ってから環境を整えようとして詰む**
ログイン機能や本の登録機能を先に作り、後から「Gitに記録して公開しよう」と考えると、既に秘密情報がコードに直書きされていたり、不要なファイルがGitに記録されていたりする。取り除く作業は、最初から避けるより手間がかかる。Phase 4の手順1に戻り、環境を先に整えてから機能に進む。

**秘密情報を`.env`に書いたままコミットしてしまう**
`.gitignore` に追加し忘れたまま、実際の値が入った設定ファイルをコミットしてしまう。第4部（安全編）の最低ラインの1つ目に触れる事故だ。コミットする前に、含めてよいファイルかを確認する。事故に気づいたら、Phase 4の手順5に戻り、`.gitignore` を見直す。
