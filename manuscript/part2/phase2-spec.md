# Phase 2 仕様を書く

## このフェーズの目的

Phase 1で決めた1文とやらないことリストを、実際の画面と機能に落とし込む。
機能は最初にできるだけ広く挙げ、そこから外すものを決める。挙げてから削るほうが、最初から絞り込むより漏れが少ない。
このフェーズを終えると、最初のバージョンで作る範囲が確定する。

## 成果物

- 画面一覧
- 機能一覧（「〜できる」の形で列挙したもの）
- 最初のバージョンに入れない機能と、その理由のリスト

## 手順

1. 画面を洗い出す。紙に描いてよい。Phase 1で決めた「誰が」「いつ」使うかを思い出しながら、その人が操作する順に並べる
2. 機能を「〜できる」の形で、思いつく限り列挙する。この時点では絞り込まない
3. 列挙した機能を「必須」「あったほうがいい」「今回は不要」の3段階に分ける
4. 「あったほうがいい」と「今回は不要」に分類した機能について、AIに外す理由を指摘させる
5. 残った「必須」の機能を、最初のバージョンの最小構成として確定する

通し課題ReadLogでは、この手順を踏んで画面を5つ（ログイン、新規登録、本の一覧、本の登録・編集、本の詳細）に、機能を8つ（ユーザー登録、ログイン、ログアウト、本の登録、一覧表示、詳細表示、編集、削除）に確定した。表紙画像のアップロードや読書ペースのグラフ化といった機能は、次のプロンプトで外す理由を明確にしたうえで見送った。

## よくある失敗と戻り先

**全部が「必須」になっている**
優先度を3段階に分けたつもりが、どれも手放せず「必須」に集まってしまう。これはPhase 1のやらないことリストが機能していないサインだ。Phase 1に戻り、やらないことリストを見直す。「作らないもの」が具体的であるほど、Phase 2で外す判断がしやすくなる。

**画面の洗い出しを飛ばして機能だけ列挙する**
機能を思いつくままに並べると、どの画面でその機能を使うのかが後で分からなくなる。結果として、Phase 3で画面ごとのデータの流れを設計するときに手戻りが起きる。Phase 2の手順1に戻り、画面から洗い出し直す。
