# Phase 1 決める

## このフェーズの目的

Phase 0で絞った案を、他人に読んで伝わる形に固定する。
このフェーズの本題は「やらないこと」を先に決めることにある。作りたい機能を並べるのは後のPhase 2で行う。ここで決めるのは範囲の外側、つまり手を出さない部分だ。
範囲を決めずに実装へ進むと、機能が際限なく増えていく。

## 成果物

- `README.md` の冒頭数行（1文の説明、誰が使うか、いつ使うか）
- やらないことリスト（3項目以上）

`README.md` は、アプリの目的や使い方を書く定番のファイルだ。リポジトリを開いた人が最初に読む場所になる。

通し課題ReadLogでは、この段階で次のように固定した。「ログインした個人が、読んだ本のタイトルと感想、読了日を記録し、一覧で振り返れるアプリ」。誰が使うかは「自分1人」、いつ使うかは「本を読み終えた直後」とした。

## 手順

1. Phase 0で書いた1文を、専門用語を使わずに他人が読んで理解できる形に書き直す
2. 誰が使うかを1行で書く。年齢や職業ではなく、どんな状況にいる人かを書く
3. いつ使うかを1行で書く。使う場面が具体的になるほど、後の機能の要不要を判断しやすくなる
4. やらないことを3つ以上書き出す。「やりたいこと」ではなく「今回は手を出さないこと」を書く
5. `README.md` を作り、1〜4の内容を冒頭にまとめる

## AIへのプロンプト雛形

> 以下の1文の説明を、プログラミング未経験の人にも伝わるように書き直してください。専門用語を使わず、誰の何が楽になるアプリかを明確にしてください。
>
> 〇〇

書き直した1文をもとに、やらないことの洗い出しに移る。

> このアプリについて、最初のバージョンでは作らなくてよい機能や要素を指摘してください。私が思いついていないものを優先して挙げてください。褒めないでください。

## 完了条件

- [ ] 1文の説明を他人に読んで伝えられる
- [ ] 誰が使うかを1行で書けている
- [ ] いつ使うかを1行で書けている
- [ ] やらないことを3つ以上書き出している

## よくある失敗と戻り先

**やらないことが1つも出てこない**
作りたい機能ばかりが浮かび、やらないことを聞かれても手が止まる。この状態のまま進むと、Phase 2で機能一覧の全部が「必須」になる。Phase 0に戻り、面倒さの絞り込みからやり直す。作るものの輪郭が曖昧なままだと、やらないことも決められない。

**1文が専門用語だらけで他人に伝わらない**
「データベースでユーザーごとに本を管理するCRUDアプリ」のように、技術の言葉で説明してしまう。技術を知らない人に読んでもらい、伝わるかを確認する。伝わらなければPhase 1の手順1に戻り、書き直す。
