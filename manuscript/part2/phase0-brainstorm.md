# Phase 0 壁打ちする

## このフェーズの目的

このフェーズは、作るものがまだ決まっていない状態から始まる。
「何を作りたいか」ではなく「何が面倒か」から出発する。作りたいものから考えると、技術的な見栄えのするアイデアに寄りやすく、実際に使い続けられるものから遠ざかる。
AIとの壁打ちを使って候補を広げ、自分で1つに絞り込む。

## 成果物

このフェーズの成果物はファイルではない。「作るものは〇〇だ」と1文で言えるメモだ。
チャットの最後の発言やメモ帳に、その1文を書き残しておく。次のPhase 1で、このメモをもとに `README.md` の冒頭を書く。

本書の通し課題は、この手順を踏んで「読んだ本の感想をすぐ忘れる。メモはノートとスマホにバラバラで残っている」という面倒さから、読書記録アプリ「ReadLog」に絞り込んだという想定で進める。

## 手順

1. 自分が普段感じている「面倒だ」を、思いつくだけ書き出す。技術的に作れるかどうかはまだ考えない
2. 書き出した面倒さの中から1つを選び、AIに解決アイデアを広げさせる。このとき出す指示を発散と呼ぶ。案を絞らず数を出させる指示のことだ
3. 出てきた案それぞれについて、AIに実現可能性の穴を指摘させる。似たサービスが既にあるか、個人の手に負える規模かを確認する
4. 穴の指摘を踏まえて、作るものを自分で1つに絞る。案を1つに絞る判断は、AIではなく自分がする
5. 絞った案を1文で書く。「〇〇な人が、〇〇できるアプリ」の形にすると書きやすい

## AIへのプロンプト雛形

> 私は〇〇が面倒だと感じています。これを解決する小さなアプリのアイデアを、実装難易度の低い順に5つ出してください。それぞれ「誰の何が楽になるか」を1行で添えてください。まだ技術の話はしないでください。

プロンプトとは、AIに対して出す指示や質問の文章を指す。これは案を広げるプロンプトだ。候補が出たら、その中から気になるものを選び、次のプロンプトでリスクだけを指摘させる。

> このアイデアについて、初心者が個人で作りきれない可能性のある要素を指摘してください。褒めるのではなく、リスクだけを挙げてください。

2つのプロンプトを分けているのには理由がある。1つ目で広げ、2つ目で絞る。1つのプロンプトで両方を頼むと、AIは無難な案に丸めてくる。

## 完了条件

- [ ] 自分が感じている「面倒だ」を1文で言える
- [ ] AIに出させた候補を3つ以上比較した
- [ ] 似たサービスの有無を確認した
- [ ] 作るものを1文で書けている

## よくある失敗と戻り先

**AIに褒められて規模を見誤る**
案を出したあと「これはいいアイデアですね」と肯定的な反応だけを受け取り、規模の大きさに気づかないまま次に進んでしまう。AIは同意しやすい返答をする性質がある。褒め言葉を信用せず、2つ目のプロンプトでリスクだけを聞き直す。戻り先はPhase 0の手順3。

**技術の話に早く入りすぎる**
「どの言語で作るか」「どのライブラリを使うか」をこの段階で決めようとすると、作るもの自体が固まらないまま技術選定に時間を使ってしまう。技術を決めるのはPhase 3からだと決め、Phase 0では1文の説明だけを目標にする。戻り先はPhase 0の手順1。
