# 用語 初出管理表

用語を本文で初出説明したら、必ずここに追記する。
書く前にこの表を見て、既出なら説明を繰り返さず前を参照させる。

| 用語 | 初出の章 | 用語集に載せるか | 備考 |
|---|---|---|---|
| フロントエンド | 第1部 1-5 | ○ | 「画面」の担当として3層の1つに導入 |
| バックエンド | 第1部 1-5 | ○ | 「処理」の担当として3層の1つに導入 |
| データベース | 第1部 1-5 | ○ | 「保存」の担当として導入。保存先3種の比較でも再言及 |
| 実行環境 | 第1部 1-5 | × | 用語集候補になし。ローカル／公開の前提として導入 |
| ポート | 第1部 1-5 | × | 用語集候補になし。実行環境の説明に付随して導入 |
| HTTP | 第1部 1-5 | ○ | 通信の共通規格として導入 |
| リクエスト／レスポンス | 第1部 1-5 | ○ | HTTPのやり取りの2動作として導入 |
| リポジトリ | 第1部 1-5 | ○ | Gitの説明と同時に導入 |
| コミット | 第1部 1-5 | ○ | 「戻せる」操作としてGitの説明内で導入 |
| ライブラリ | 第1部 1-5 | ○ | 他人のコードを借りる部品として導入 |
| 依存関係 | 第1部 1-5 | ○ | ライブラリとバージョンの関係として導入 |

## 用語集（第6部）のエントリ形式

```markdown
### 用語名
**一言で**：（1文）
**もう少し詳しく**：（2〜4文）
**これが分かると**：（本書のどこで効くかを具体的に）
```

3段目が書けない用語は載せない。辞書化を防ぐための歯止め。

## 用語集に入れる候補

- 開発の流れ：リポジトリ、コミット、ブランチ、マージ、環境変数、デプロイ、CI
- アプリの構造：フロントエンド、バックエンド、API、データベース、フレームワーク、ライブラリ、依存関係
- 通信：HTTP、リクエスト／レスポンス、ステータスコード、JSON、エンドポイント
- 安全：認証、認可、ハッシュ化、暗号化、脆弱性、サニタイズ
- AI関連：コンテキスト、ハルシネーション、トークン、プロンプト
